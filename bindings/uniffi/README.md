# chromahash-uniffi — Android binding

The Rust ChromaHash core ([`rust/`](../../rust/), crate `chromahash`) exposed to Kotlin/Android
over JNI via [UniFFI](https://mozilla.github.io/uniffi-rs/), packaged as an AAR. This is the fast,
SIMD-ready path for **decoding** placeholders on-device. See [`docs/android.md`](../../docs/android.md)
for the rationale and trade-offs vs. the pure-Kotlin implementation.

## Layout

```
bindings/uniffi/
├── Cargo.toml            # chromahash-uniffi crate (cdylib + staticlib + lib)
├── src/lib.rs            # UniFFI wrappers around the core API
├── uniffi-bindgen.rs     # the uniffi-bindgen CLI entry point
├── uniffi.toml           # generated-Kotlin package = io.chromahash.ffi
├── tests/spec_vectors.rs # spec-vector correctness gate (no NDK needed)
└── android/              # Gradle library module → AAR
    ├── build.gradle.kts  # com.android.library (AGP 9) + vanniktech maven-publish + cargo-ndk/bindgen tasks
    └── src/main/
        ├── kotlin/       # GENERATED by uniffi-bindgen (gitignored)
        └── jniLibs/      # GENERATED by cargo-ndk, one .so per ABI (gitignored)
```

The generated Kotlin and the `.so` files are build outputs — gitignored and regenerated; never
committed or hand-edited.

## API

The generated `io.chromahash.ffi` API mirrors the pure-Kotlin `chromahash` API:

| Pure Kotlin (`chromahash`)             | Native (`io.chromahash.ffi`)              |
| -------------------------------------- | ----------------------------------------- |
| `ChromaHash.encode(w, h, rgba, gamut)` | `ChromaHash.encode(w, h, rgba, gamut)`    |
| `ChromaHash.fromBytes(bytes)`          | `ChromaHash.fromBytes(bytes)` — `@Throws` |
| `chromaHash.decode(): DecodeResult`    | `chromaHash.decode(): DecodeResult`       |
| `chromaHash.averageColor(): RgbaColor` | `chromaHash.averageColor(): RgbaColor`    |
| `chromaHash.hash: ByteArray`           | `chromaHash.asBytes(): ByteArray`         |
| —                                      | `chromaHash.decodeCapped(maxW, maxH)`     |
| `Gamut` enum                           | `Gamut` enum                              |

Two deliberate FFI-boundary differences from the doc's original sketch:

- **`fromBytes` is fallible** — it throws `ChromaHashException.InvalidLength` if the input's
  length is not the one its own header declares (a panic across FFI is unsafe). That is 32 bytes
  at the default tier, 21 at the compact one and 108/411/1623 above it, less if the alpha flag is
  set; §3.5 gives the formula. Catch it, or validate length first.
- **Record ints are signed** (`DecodeResult.width/height: Int`, `RgbaColor.r/g/b/a: Int`) for
  drop-in parity with the pure-Kotlin API and with `Bitmap`/ARGB call sites. Size *parameters*
  (`encode`'s `w`/`h`, `decodeCapped`'s `maxW`/`maxH`) are `UInt`.

Migration from the pure-Kotlin impl is mostly swapping the import
(`chromahash.ChromaHash` → `io.chromahash.ffi.ChromaHash`) and handling the `fromBytes` exception.

## Develop / test (no Android toolchain required)

These run on any host with a Rust toolchain — they are the enforced correctness gate (hk
pre-push + CI), and they validate the marshalling layer against the shared `spec/` test vectors:

```bash
mise run test:android          # spec vectors through the binding (byte-exact)
mise run lint:android          # clippy -D warnings
mise run format:check:android  # rustfmt --check
mise run build:android:crate   # host build of the crate (lib + cdylib + bindgen bin)
```

## Build the AAR (requires the Android NDK)

Prerequisites:

```bash
# cargo-ndk is mise-managed (see .mise.toml) — installed by `mise install`
mise install
# Rust Android targets (rustup-managed)
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android i686-linux-android
# An NDK (install via Android Studio → SDK Manager → SDK Tools → NDK, or sdkmanager)
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/<version>"
```

Then:

```bash
mise run build:android:aar     # cargo ndk (all ABIs) → uniffi-bindgen → gradle assembleRelease
```

The Gradle `assembleRelease` task wires the native steps automatically (`preBuild` depends on
`cargoNdkBuild` → `generateUniffiBindings`), so the single command produces:

```
android/build/outputs/aar/chromahash-android-release.aar   # jni/<abi>/libchromahash_uniffi.so + classes.jar
```

Drop ABIs you don't ship (edit `abis` in `android/build.gradle.kts`) to shrink the AAR;
`arm64-v8a` covers essentially all modern physical devices.

## Consume from an app

```kotlin
import android.graphics.Bitmap
import io.chromahash.ffi.ChromaHash
import java.nio.ByteBuffer

/** Decode a ChromaHash into a Bitmap placeholder. */
fun decodeToBitmap(hashBytes: ByteArray): Bitmap {
    val hash = ChromaHash.fromBytes(hashBytes)        // throws unless the length matches the header
    val result = hash.decode()
    val bitmap = Bitmap.createBitmap(result.width, result.height, Bitmap.Config.ARGB_8888)
    bitmap.copyPixelsFromBuffer(ByteBuffer.wrap(result.rgba))
    return bitmap
}
```

For a solid-color placeholder, skip the full decode and use the DC color:

```kotlin
val c = ChromaHash.fromBytes(hashBytes).averageColor()
val argb = (c.a shl 24) or (c.r shl 16) or (c.g shl 8) or c.b
```

> **Pixel order / alpha.** Decode output is RGBA, which `ARGB_8888` stores as `R, G, B, A` in
> native memory, so `copyPixelsFromBuffer` consumes it directly. `ARGB_8888` Bitmaps are
> premultiplied by default — premultiply yourself or set `bitmap.setPremultiplied` if your
> placeholders carry partial alpha.

## Publish

The AAR publishes via the [vanniktech maven-publish](https://vanniktech.github.io/gradle-maven-publish-plugin/)
plugin to **Maven Central** and **GitHub Packages** as `io.github.visualcommons:chromahash-android`
(the Kotlin package stays `io.chromahash.ffi` — it is independent of the Maven group):

```bash
# local development
./gradlew publishToMavenLocal

# Maven Central (Sonatype Central Portal) — needs the signing + Portal token env vars
./gradlew publishAndReleaseToMavenCentral

# GitHub Packages (CI sets GITHUB_ACTOR/GITHUB_TOKEN; locally set gpr.user/gpr.key)
./gradlew publishMavenPublicationToGitHubPackagesRepository
```

Releases happen automatically on a `vX.Y.Z` tag via the
[`release-android`](../../.github/workflows/release-android.yml) workflow. The one-time Maven
Central bootstrap (namespace, signing key, secrets) is documented in
[RELEASING.md](../../RELEASING.md#publishing-the-android-aar).

### Consume from Maven Central

```kotlin
dependencies {
    implementation("io.github.visualcommons:chromahash-android:X.Y.Z")
}
```

No repository config beyond `mavenCentral()` and no consumer auth is required.

## Optional: end-to-end check through the generated Kotlin

The Rust spec-vector test validates the binding's Rust side. To additionally validate the
*generated Kotlin* over a real JNA/FFI call without an emulator, build a host cdylib
(`cargo build --release`), generate Kotlin from it
(`cargo run --bin uniffi-bindgen -- generate target/release/libchromahash_uniffi.so --language kotlin --out-dir <dir> --config uniffi.toml`),
then run the spec vectors from a JVM with JNA on the classpath and `jna.library.path` pointed at
the host `.so`. This is not wired into CI — the AAR job's `assembleRelease` already compiles the
generated Kotlin.
